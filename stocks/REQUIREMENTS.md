# 個別株ウォッチ・ダッシュボード 要件案 (v0.1 ドラフト)

> 本ドキュメントは実装前の**要件たたき台**です。「要決定」と記した箇所を確定させてから設計・実装に進みます。
> 本ツールは投資助言を行うものではなく、**自分の意思決定プロセスを記録・可視化する個人用ツール**です。

---

## 1. 目的とゴール

### 1.1 解きたい課題

個別株の意思決定（買う／買わない／持ち続ける／売る）は、判断時点の指標と、そのとき自分が何を考えたかがセットで残っていないと再現も検証もできない。証券会社のアプリは「今の値」は見せてくれるが、**過去の自分の判断根拠と指標の推移を並べて振り返る**ことができない。

### 1.2 ゴール

| # | ゴール | 達成の判定基準 |
|---|--------|----------------|
| G1 | 銘柄ごとの主要指標を一目で把握できる | 銘柄詳細を開いて5秒以内に「割安か・稼げているか・財務は健全か」が判別できる |
| G2 | 指標の推移を時間軸で追える | 任意の指標を1年／3年／5年スパンで折れ線・棒グラフで表示できる |
| G3 | 判断とその根拠を時点で残せる | 「2026-08-14 に PER 12倍・配当利回り 4.2% で打診買い」といった記録が後から検索できる |
| G4 | 複数銘柄を横並びで比較できる | ウォッチ中の銘柄を指標でソート・スクリーニングできる |
| G5 | 判断の答え合わせができる | 過去の判断メモに、その後の株価推移を重ねて表示できる |

### 1.3 非ゴール（やらないこと）

- 自動売買・発注機能
- リアルタイム株価（ティック単位）の配信
- 投資助言・推奨銘柄の提示（スコアはあくまで自分で定義したルールの計算結果）
- 税務計算・確定申告書類の作成

## 2. 想定利用シーン

| シーン | 頻度 | やること |
|--------|------|----------|
| S1 銘柄スクリーニング | 月1〜2回 | 一覧を指標でソートし、候補をウォッチに追加 |
| S2 決算チェック | 四半期ごと | 決算発表後に指標スナップショットを更新、前期比の変化を確認 |
| S3 買い場の見極め | 週1回 | 株価チャートと指標（利回り・PER）のレンジ内位置を確認 |

| S5 振り返り | 半年〜1年 | 過去の判断メモとその後の株価を照合し、判断の質を検証 |

## 3. 管理する指標（案）

指標は**カテゴリ単位でカードにまとめ、カテゴリごとに表示ON/OFFを切り替えられる**構成とする。投資スタイル（バリュー／配当／グロース／テクニカル）によって重視する指標が変わるため、**「表示プリセット」を選べる**ようにする。

### 3.1 基本情報（マスタ）

| 項目 | 型 | 備考 |
|------|-----|------|
| ティッカー／証券コード | 文字列 | 日本株は4桁コード、米国株はシンボル |
| 銘柄名 | 文字列 | |
| 市場・上場区分 | 文字列 | プライム／スタンダード／グロース、NYSE／NASDAQ |
| 業種（セクター） | 文字列 | 東証33業種 or GICS。**要決定：分類体系の統一方法** |
| 通貨 | 文字列 | JPY／USD |
| 決算期（期末月） | 数値 | 四半期スナップショットの基準 |
| 自分のタグ | 配列 | 「高配当」「優待あり」「本命」など自由タグ |

### 3.2 バリュエーション（割安度）

| 指標 | 更新頻度 | 可視化の要点 |
|------|----------|--------------|
| 株価 | 日次 | ローソク足 or 終値ライン |
| 時価総額 | 日次 | |
| PER（実績・予想） | 日次 | **過去5年レンジ内の位置**をバンド表示（割安判定の肝） |
| PBR | 日次 | 同上。1倍割れラインを明示 |
| PSR | 四半期 | グロース株向け |
| EV/EBITDA | 四半期 | 負債込みの割安度 |
| PEG レシオ | 四半期 | 成長を加味した PER |
| 益回り（PERの逆数） | 日次 | 国債利回りとの比較で表示すると判断しやすい |

> **設計上の要点**: 単独の PER 15倍は割安とも割高とも言えない。**同一銘柄の過去レンジ**と**同業他社の中央値**の2つの物差しを常に添えることを必須要件とする。

### 3.3 収益性・成長性

| 指標 | 更新頻度 | 可視化の要点 |
|------|----------|--------------|
| 売上高 | 四半期 | 棒グラフ＋YoY成長率の折れ線を重ねる |
| 営業利益・営業利益率 | 四半期 | 利益率のトレンドが鈍化していないか |
| 純利益・EPS | 四半期 | |

| ROE | 四半期 | 8%ラインを基準線として表示（日本株の目安） |
| ROA / ROIC | 四半期 | |
| 会社予想（通期ガイダンス） | 随時 | **予想の上方／下方修正をイベントとして記録** |
| 進捗率（通期予想に対する累計実績） | 四半期 | 決算チェック時の主要判断材料 |

### 3.4 財務健全性

|------|----------|--------------|

| ベータ | 四半期 | |

### 3.7 自分の判断記録（本ツール独自の価値）

|------|-----|------|

## 4. 時間軸の扱い（本要件の中核）

「時間軸を追いやすい形」を実現するため、データを**更新頻度の異なる3レイヤー**に分離して保持する。すべてのレイヤーが日付をキーに持つため、同一の時間軸に重ねて描画できる。

```
レイヤー1: 日次時系列 (prices)
  株価・出来高・そこから算出するテクニカル指標
  → 毎営業日1レコード。自動取得の対象。

レイヤー2: 期別スナップショット (fundamentals)
  決算期（四半期／通期）ごとの財務・バリュエーション指標
  → 決算発表ごとに1レコード。「いつ時点の数字か」を必ず保持。

レイヤー3: イベント／判断ログ (events / decisions)
  自分の売買判断、業績修正、増配、株式分割などの出来事
  → 発生ごとに1レコード。チャート上にマーカーとして描画。
```

### 4.1 スナップショット方式の原則

- **上書きしない**。指標を更新するときは既存レコードを書き換えず、新しい日付のレコードを追加する。これにより「あのとき何を見て判断したか」が必ず復元できる。
- 各レコードに `as_of`（その数字が指す時点）と `recorded_at`（記録した日時）を両方持つ。決算は「3月期の数字を5月に記録する」ため、この2つは必ずずれる。
- 修正が必要な場合は、レコードに `revision` を付けて追記する（削除ではなく訂正履歴として残す）。

### 4.2 時間軸ビューの要件

| # | 要件 |
|---|------|
| T1 | 期間セレクタ（1年／3年／5年／全期間／カスタム）で全チャートが連動して切り替わる |
| T2 | 株価チャート上に、判断ログとイベントをマーカーで重畳表示できる |
| T3 | マーカーにホバー／タップすると、その時点の判断メモと指標スナップショットがポップアップする |
| T4 | 任意の2指標を同一チャートに重ねられる（例: 株価 と 配当利回り、EPS と 株価） |
| T5 | 指標の「過去レンジ内の現在位置」をバンド／ゲージで表示する |
| T6 | 決算発表日を縦線で表示し、決算前後の値動きを視認できる |

```jsonc

  "lastUpdated": "2026-08-14",
  "settings": {
    "thresholds": { "per_low": 15, "pbr_low": 1.0, "roe_good": 8, "payout_high": 80 },

  "stocks": [
    {
      "id": "uuid",
      "ticker": "7203",
```

### 6.1 保有・損益管理（要決定）

保有数量・取得単価まで管理するかで、必要な機能が変わる。
- **含める場合**: 取得単価の加重平均計算、評価損益、ポートフォリオ全体の構成比・セクター配分の可視化が可能になる。反面、約定履歴の入力が必要で運用負荷が上がる。
- **含めない場合**: 指標の観測と判断記録に集中でき、証券会社アプリと役割分担できる。

> **推奨**: v1 は「判断ログに数量を任意項目として持たせる」に留め、ポートフォリオ集計は v2 で追加する。データモデル上は最初から `quantity` を持たせておき、後から集計機能を足せるようにする。

## 7. データの入力・更新方式

### 7.1 想定する3つの経路

| 経路 | 対象データ | 実現方法 |
|------|-----------|----------|
| A. 手入力 | 決算指標、判断メモ、タグ、しきい値 | 画面のフォームから入力 |
| B. 自動取得 | 株価・出来高（日次） | GitHub Actions + Python スクリプトで定期取得し `data.json` を更新 |
| C. 一括取込 | 既存の記録、証券会社からのCSV | JSON/CSV インポート |

### 7.2 自動取得の制約（要検討事項）

- **米国株**: 無料で利用できるAPIの選択肢があり、日次終値の取得は比較的容易。
- **日本株**: 無料APIは選択肢が限られ、利用規約・信頼性・レート制限の確認が必須。**実装前に対象APIの規約を個別に確認する**。取得できない場合は手入力またはCSV取込にフォールバックする設計とする。
- APIキーが必要な場合は GitHub Secrets に格納し、クライアント側のコードには絶対に埋め込まない（既存のメルマガ更新ワークフローと同じ方式）。

> **推奨**: v1 は**手入力ベースで完成させる**。自動取得は「あれば便利」だが、これが無いと始められない設計にすると、API選定で全体が止まる。データモデルは自動取得を後から差し込める形にしておく。

### 7.3 永続化の方式（既存アプリの型を流用）

restaurant アプリで実績のある3段構えをそのまま採用する。

1. **localStorage**: 主たる作業領域。オフラインでも動作
2. **`stocks/data.json`**: リポジトリ上の正となるデータ。初回読込のシードにもなる
3. **GitHub Contents API 同期**: Fine-grained PAT を localStorage に保持し、画面から push/pull。加えて JSON エクスポート／インポートも備える

## 8. 非機能要件

| # | 分類 | 要件 |
|---|------|------|
| N1 | 稼働環境 | GitHub Pages 上の静的サイト。バックエンドサーバを持たない |
| N2 | 技術構成 | 単一 HTML ファイル完結（既存アプリと同様）。外部CDN依存を避け、必要なライブラリはリポジトリに同梱する |
| N3 | 性能 | 銘柄50件・各5年分の日次データ（約1,300点／銘柄）で、一覧描画1秒以内 |
| N4 | データ量 | 上記規模で `data.json` が肥大化するため、**日次株価は銘柄別ファイルに分割**するか、保持期間を限定する。**要決定** |
| N5 | セキュリティ | GitHub PAT はデバイスの localStorage のみに保持。リポジトリが public であることを前提に、**保有数量・資産額など公開したくない情報を置くかは要決定** |
| N6 | 可搬性 | いつでも JSON をエクスポートでき、ツールを捨てても記録が残る |
| N7 | オフライン | 閲覧・入力はオフラインで可能（同期時のみ通信） |

> **N5 は最重要の要確認事項**。このリポジトリは GitHub Pages で公開されているため、**保有数量・取得単価・資産額を `data.json` に置くと第三者から閲覧可能になる**。対応案は以下。
> 1. 金額に関わる情報は localStorage のみに保持し、リポジトリには同期しない
> 2. 別のプライベートリポジトリにデータだけを置き、そこと同期する
> 3. 保有情報は管理せず、指標と判断メモのみを扱う

## 11. 補足：この設計の考え方

本ツールの価値は**指標を表示すること**ではなく（それは証券会社のアプリで足りる）、**「そのとき自分がどう考えたか」を指標と一緒に時系列で残すこと**にある。

したがって設計上の優先順位は次のとおりとする。

1. 判断ログが確実に残ること（データの不可逆性・可搬性）
2. 過去の判断を、その時点の指標と一緒に呼び出せること
3. 指標の推移が直感的に読めること
4. 指標が自動で最新化されること ← **最優先ではない**

4 を最優先にすると API 選定でプロジェクトが止まる。1〜3 は手入力だけでも成立し、そこにこそ他ツールで代替できない価値がある。
