# ガチャ入荷カレンダー

毎週追加されるガチャガチャ（カプセルトイ）のラインアップから「回したいもの」を選び、
入荷めどをカレンダーで見える化して、入荷めどに合わせた店舗調査を漏れなく行うためのツール。

公開URL: `https://bo0639.github.io/hijiri.github.io/gacha/`（GitHub Pages）

## 要件定義

| 項目 | 決定内容 |
|---|---|
| 入荷情報の登録 | **手入力 ＋ 自動収集**。メーカー公式の発売スケジュールを GitHub Actions で週2回（月・木 7:00 JST）収集し、「🆕 ラインアップ」で ☆ を押すと「回したい」に登録できる |
| 店舗調査 | **店舗マスタ ＋ 巡回記録**。よく行く店舗を登録し、商品×店舗ごとに調査結果を記録する |
| あいまいな入荷めど | **期間（開始日〜終了日）として持ち、カレンダーに帯で表示**。日付・第N週・上中下旬・月内のどれでも入力できる |
| リマインド | **画面内アラートのみ**（ホームのタイル・セクション、ナビのバッジ） |
| データ更新 | **Claude Code で `gacha/data.json` を更新してPRをマージする**（ポケカ抽選トラッカーと同じ運用）。ツールのURLは固定で、同じURLを開くだけで最新が表示される。画面上でも編集でき、任意でGitHub同期も使える |

### 入荷めどの書き方

| 入力例 | 扱い |
|---|---|
| `10月18日` / `10/18` / `2026/10/18` | 日付確定（カレンダーは塗りつぶしの帯） |
| `10月第2週` / `10月第2〜3週` / `10月第4週〜11月第1週` | 週単位（月曜はじまり、1日を含む週を第1週とし、月内に収める） |
| `10月5日週` | その日から1週間（タカラトミーアーツの表記） |
| `11月上旬` / `11月中旬〜下旬` | 旬単位（上旬1〜10日・中旬11〜20日・下旬21日〜月末） |
| `12月` / `2027年1月発売予定` | 月単位 |

週・旬・月の「めど」はカレンダーで**斜線＋点線の帯**、日付確定は**塗りつぶしの帯**で表示し、確度の違いが一目で分かるようにする。
年を省略した場合は、今日から見て近い年（約4か月前〜8か月先）として解釈する。

ラインアップから登録した商品は、入荷めどを手で直していなければ、公式の発売予定が更新されたときに**入荷めども自動で追従**する（「めど更新」バッジで通知）。

### 画面

| 画面 | 内容 |
|---|---|
| 🏠 ホーム | 状況タイル（今が探し時／1週間以内に入荷／めどの確認待ち／新着ラインアップ）、**店舗の調査マップ**（商品×店舗の表。マスをタップして記録）、今が探し時、1週間以内に入荷めど、入荷めどを確認しよう、めどを大きく過ぎた |
| 📅 カレンダー | 月曜はじまりの月表示。行の左に「第N週」を表示（公式の「第N週」表記と対応）。帯は優先度で色分け。「＋ラインアップ」で未登録の新作も薄く表示。週をタップするとその週の一覧を表示 |
| ⭐ 回したい | 登録した商品の一覧（状態・優先度で絞り込み、検索） |
| 🆕 ラインアップ | 自動収集した発売予定（月ごと、メーカー絞り込み、NEW／めど変更バッジ、☆で登録）。収集元ごとの成功／失敗も表示 |
| 🏪 店舗 | 店舗の登録・並べ替え（巡回順）・地図リンク。店舗ごとに「ここで確認すること」を表示 |

### 判定ルール

- **探し時**: 入荷めどの期間中、または終了後21日以内の「狙う」商品
- **1週間以内に入荷**: 入荷めどの開始まで7日以内
- **めどの確認待ち**: 入荷めどが「月」「旬」のまま、開始まで21日以内（公式で週・日付を確認して更新をうながす）
- **めどを大きく過ぎた**: 入荷めどの終了から21日を超えた未入手（続けるか見送るか判断をうながす）
- **調査結果**: ⏳未入荷／◎在庫あり／△残りわずか／✕売切れ／−取扱なし／★回した
  - 「未入荷」から3日以上経った店は「再確認」として薄く表示する
  - 売切れ・取扱なし・回した の店は、その商品の「確認すること」から外す
  - 「回した」を記録すると、その商品を「ゲット済」にできる

## 運用（ポケカ抽選トラッカーと同じ）

- **データの更新は Claude Code で行う。** 依頼を受けた Claude Code が `gacha/data.json` を編集し、PRをマージする
- **ツールのURLは固定**: `https://bo0639.github.io/hijiri.github.io/gacha/`。マージ後1〜2分で GitHub Pages に反映され、PC・スマホとも同じURLを開く（開き直す・アプリに戻る）だけで最新の共有データが表示される
- 画面上での追加・編集・調査記録もできる。同期（下記）を設定していない端末では、その端末だけに保存される
- 共有データと端末のデータは **idごとに `updated_at` が新しい方** を採用して合わせる。削除は `deleted` に入れたidで伝わる

### Claude Code での更新手順

1. 依頼内容を `gacha/data.json` に反映する（形式は下表）。変更・追加した要素の `updated_at` は**必ず現在時刻**（UTCのISO形式、例 `2026-10-05T03:00:00.000Z`）にする。古いままだと、端末側のデータが優先されて反映されない
2. 入荷めど（`arrival`）は手で計算せず、スクリプトで作る:
   `python scripts/update_gacha_lineup.py --arrival "10月第2週"` → `{"kind": "week", "label": "10月第2週", "from": "2026-10-05", "to": "2026-10-11"}`
3. 公式ラインアップにある商品は、`feed.json` から探して `feed_id`・`name`・`maker`・`price`・`image`・`url`・`arrival` を写す（`feed_id` があると、公式の入荷めどが更新されたとき自動で追従する）:
   `python scripts/update_gacha_lineup.py --find "mofusand めじるし"`
4. 削除するときは要素を消し、そのidを `deleted` に追加する（商品・店舗を消すときは、紐づく調査記録も同様に消す）
5. ブランチにコミットしてPRを作り、マージする。コミットメッセージに追加・変更した内容を箇条書きで残す

### data.json の形式

```json
{
  "items":  [{"id": "i-20261005-mofusand", "name": "mofusand めじるしアクセサリー2", "maker": "バンダイ", "price": 300,
              "arrival": {"kind": "week", "label": "10月第1週", "from": "2026-10-01", "to": "2026-10-04"},
              "priority": "want", "status": "plan", "target": "シークレット狙い",
              "url": "https://gashapon.jp/products/detail.php?jan_code=…", "image": "https://…", "note": "",
              "feed_id": "bandai-8654c79092", "created_at": "…", "updated_at": "…"}],
  "stores": [{"id": "s-aeon-kitasenju", "name": "イオン 北千住", "area": "北千住", "map": "住所または地図URL",
              "note": "", "order": 0, "created_at": "…", "updated_at": "…"}],
  "visits": [{"id": "v-20261005-001", "item_id": "i-…", "store_id": "s-…", "date": "2026-10-05",
              "result": "stock", "note": "残り2台", "updated_at": "…"}],
  "deleted": ["削除したid", "…"]
}
```

| 項目 | 値 |
|---|---|
| `id` | 重複しない任意の文字列（例: `i-日付-短い英字`、`s-店名`、`v-日付-連番`）。一度使ったidは使い回さない |
| `priority` | `must`（絶対）／`want`（回したい）／`maybe`（気になる） |
| `status` | `plan`（狙う）／`got`（ゲット済）／`skip`（見送り） |
| `arrival.kind` | `date`／`week`／`jun`／`month`／`range`。`--arrival` の出力をそのまま使う |
| `arrival_manual` | `true` にすると、`feed_id` があっても公式の入荷めどに追従しない（手で決めた入荷めどを守りたいとき） |
| `visits.result` | `before`（未入荷）／`stock`（在庫あり）／`low`（残りわずか）／`soldout`（売切れ）／`none`（取扱なし）／`played`（回した） |
| `stores.order` | 巡回順（0から） |

## PCとスマホの同期（任意）

ポケカ抽選トラッカーと同じく、PC・スマホの両方で「⋯ → スマホと同期（GitHub）」にトークンを設定すると、画面上での編集もGitHub経由で共有される（Claude Codeでの更新だけで運用するなら設定は不要）。

- 変更すると約1.5秒後にGitHubへ保存する。アプリを閉じる・切り替えるときに保存待ちの変更があれば、その場で送る
- アプリを開いたとき、別のアプリから戻ってきたとき（前回から20秒以上経過）に、共有データ・他の端末の変更を取り込む
- 突き合わせは idごとに更新日時が新しい方を採用する。PCとスマホで別々に編集しても両方の変更が残り、削除は `deleted` で伝わる
- 保存の直前に他の端末（または Claude Code のマージ）が保存していた場合は、取り込み直してから保存し直す（最大3回）

## データ

| ファイル | 内容 | 更新者 |
|---|---|---|
| `gacha/data.json` | 回したい商品・店舗・調査記録・削除済みid `{items, stores, visits, deleted}` | アプリ（GitHub同期） |
| `gacha/feed.json` | 自動収集したラインアップ | GitHub Actions |
| `gacha/sources.json` | 自動収集の取得元設定 | 手で編集 |

## 自動収集（scripts/update_gacha_lineup.py）

- 標準ライブラリのみで動作。`.github/workflows/update_gacha_lineup.yml` から月・木の朝に実行（Actions画面から手動実行も可）
- 各サイトのHTML構造に依存しないよう、「商品ページへのリンクを含む小さなまとまり」を探し、その中の価格・入荷めど、無ければ直前の見出し（例:「10月第2週」）を採用する汎用抽出を行う
- 取得に失敗したソースは、前回の収集結果を残したうえで、ラインアップ画面に失敗理由を表示する
- 取得元を増やすときは `gacha/sources.json` に追記する（各項目の意味はファイル先頭の `_comment` を参照）
- 保存したHTMLで抽出を試す: `python scripts/update_gacha_lineup.py --file page.html --source bandai`

> 入荷めどの解釈ルールは `index.html` の `parseArrival()` と `update_gacha_lineup.py` の `parse_arrival()` に同じ実装があります。片方を直したらもう片方も直してください。
